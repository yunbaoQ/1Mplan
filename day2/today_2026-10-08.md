## A. 收尾第一项：硬件理解与设备验证（60 分钟）

**1. 修订概念与补硬件清单，35 分钟。**先读 [Day 1 验收反馈](../day1/A_review.md)，在 hardware_corrections.md 用自己的话写出：

- 一张常见图片训练的数据流箭头图，标明哪里存数据、哪里执行计算。
- 为什么 CPU 解码/预处理不等于 RAM 在计算。
- 为什么 GPU 训练不必把每层输出传回 CPU；CPU 什么情况下需要取回结果。
- 为什么只增大 batch_size，不能直接断定磁盘链路成为瓶颈。

补 CPU 型号、RAM 容量与 GPU 显存容量到 hardware_inventory.txt。可从系统设置/任务管理器查询，或使用下面的只读命令；任选一种即可：

```powershell
Get-CimInstance Win32_Processor | Select-Object Name
Get-CimInstance Win32_ComputerSystem | Select-Object TotalPhysicalMemory
```

`TotalPhysicalMemory` 的单位为字节；记录原值并换算 GiB。GPU 信息用当前 PyTorch 环境的设备属性查询或任务管理器确认，记录显存容量，不从型号猜测。不需要重装 PyTorch 或 CUDA Toolkit。

**2. device 对照自测，25 分钟。**自己写一个短实验：

1. 创建 CPU 张量并打印 `.device`。
2. 使用 `.to("cuda")` 得到另一个张量，分别打印原张量与返回张量的设备；解释是否必须保存返回值。
3. 用新的 `torch.ones` 给变量重新赋值，打印设备，解释它为什么可能回到 CPU。
4. 显式指定 GPU 创建设备张量，确认设备与输出。

这里只练几行张量操作，不跑大模型。CUDA 若异常先保留报错，不擅自改坏已可用的环境。输出和解释保存在 device_check.ipynb 或 .py 及笔记中。不要将 `.to` 笼统理解为一定会修改原张量或一定会复制；按这个实验的设备变化解释即可。

**验收：**硬件清单齐全；四个问题能自己讲清；CPU/GPU 张量的设备预测与实际输出一致。完成后第一项的硬件部分才标为通过。

## C. 用今天的程序练 Git 与 Linux（150 分钟）

### Git 本地记录（75 分钟）

先学工作区、暂存区、提交三个概念，再练 `init`、`status`、`add`、`commit`、`diff`、`log`。参考 [Git 官方提交记录教程](https://git-scm.com/book/en/v2/Git-Basics-Recording-Changes-to-the-Repository)。

1. 在 day2/git_practice 准备独立练习仓库，操作前用 `git rev-parse --show-toplevel` 确认是否处于已有仓库中。如果显示了父项目仓库，先保留输出并询问，不在已有仓库里改历史或建立嵌套仓库。如果提示当前不是 Git 仓库，这是初始化前的正常状态，可以在该练习目录执行 `git init`。
2. 用你的词频程序或一份练习说明完成第一次提交；提交前用 status 确认只包含你要记录的练习文件。
3. 修改一个小功能、测试或说明，用 diff 阅读差异，再完成第二次提交。
4. 将两次 `git log --oneline`、一次 diff 的输出和自己的解释保存到 git_notes.md。

Git 没安装或 commit 缺用户信息时，把完整报错记下来；先解决具体问题，不顺手发布 GitHub 或提交整个工作区。

**验收：**能解释未暂存、已暂存、已提交的区别，能说出第二次提交改了什么。命令输出比截图更方便复查。

### Linux 基本操作（75 分钟）

优先用已有虚拟机或 RK3588，在一个新建的练习目录操作；不动系统和已有项目。练习：

| 命令/概念 | 你需要观察什么 |
| --- | --- |
| pwd、ls、cd | 当前目录、文件列表、相对路径和绝对路径 |
| mkdir、cat | 建立练习目录、查看一个小文本文件 |
| ps | 找到自己启动的练习进程，记录 PID 与命令 |
| 标准输出与文件输出 | 将一次小程序的结果保存到文件，区别终端显示与文件保存 |

如果 Linux 中没有 PyTorch，可以只运行普通 Python 或系统已有小程序；这一步不要求在 RK3588 上安装 NVIDIA CUDA。将命令、作用、实际输出和遇到的问题写进 linux_basics.md。

没有可用 Linux 环境时，记录缺失条件，在笔记中做路径/进程概念自测，明确标为“未实操”，把剩余时间用于 Python 测试和 Git；明天不强制额外安装一整套虚拟机来赶进度。

**验收：**能独立进入练习目录、查看文件、区分两种路径、找到自己运行的一个进程。环境不可用时保留待实操项，不假装通过。
